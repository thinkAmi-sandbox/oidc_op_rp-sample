# 既定値への追随の記録

Ruby / Rails のアップグレードで、Rails（と周辺 gem）の既定値・雛形の変化に追随した項目を、Rails の版ごとに記録する。「挙動を変えない」の定義（[PLAN.md](../PLAN.md) の 3 章の 2）の A にあたるもの。各システムの業務的な挙動を変える「意図的な仕様変更」（B）は、PLAN.md と [LOG.md](../LOG.md) に書く。

## 記録のルール

- 1 項目 1 節。ID は `DEF-<Rails の版>-<連番>`（例: `DEF-7.0-01`）で、一度振ったら変えない。LOG.md・コミットメッセージ（`Refs: DEF-7.0-01`）からは ID で指し、内容を重複させない
- 採用しなかったもの（使っていない機能のマイグレーションなど）も、扱いを「採用しない」として残す。後の版で同じものが出たときに、前の判断を探せるようにするため
- 各節には、種類・対象のアプリ・何が変わるか・なぜ起きたか・3 アプリへの影響（確かめたこと）・扱い・出典・コミットを書く
- 出典は、Rails の PR・CHANGELOG・gem のソース（`gem名-バージョン/` から書く）と、日本語版の Rails ガイドの該当の節（ページと見出し）。ガイドは上げる先の版のページ（例: `https://railsguides.jp/v7.0/`）を使い、その版になければ最新版のページを使って、そう明記する。見出しの番号は確かめた時点のもの
- どのファイルに入れるか
  - Rails を上げる Step: 上げる先の版のファイル
  - 周辺 gem のサブステップ（1-b など）と、Ruby だけを上げる Step: そのときの Rails の版のファイル（種類に「周辺 gem」「Ruby」と書く）
- 公開物として扱う（[CLAUDE.md](../../../CLAUDE.md) の「公開物への記載ルール」）
