# 手動確認

verify と、作業計画で決めた時点から呼ぶ。ブラウザでの手動確認は、担当者が操作する（パスワードの入力、同意の操作）。

## 入口の条件

- 手動確認の時期は、作業計画で担当者と決めてある（判断の関門）
- 手動確認用の環境（設定の「手動確認用の環境」）が、作業の始めに控えた状態と同じ

## 手順

1. 手動確認用の環境を控えた状態と比べる（直前に確かめる）
2. 設定の「手動確認」の方法でアプリを起動する
3. ブラウザの画面が担当者に見えているかを確かめてから、操作を頼む。頼むときは、押すボタン・入れるもの・見てほしい画面を順に書く
4. 操作の間のサーバーの出力（エラー・警告・非推奨）と、アプリ間のやり取りを読む
5. 手動確認でデータが増えたら、件数を数え、新しい基準として控える

## 関門

- 判断の関門: 手動確認の時期
- 担当者の操作: パスワードの入力、同意

## 出口の条件と記録

- 確かめた流れ、サーバーの出力、手動確認用の環境の前後（件数と、変わったもの・変わっていないもの）を記録の下書きに控える
