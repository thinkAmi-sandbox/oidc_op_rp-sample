# gems（周辺 gem を 1 つずつ上げる）

## 入口の条件

- 作業計画が承認され、上げる gem・版・順番・一時固定が決まっている
- ダウンロードの承認を得ている

## 手順

gem ごとに、次を繰り返す。1 回に動かす gem は 1 つだけ（依存で一緒に動くものは、作業計画で決めた範囲）。

1. その gem の変化のうち、テスト・E2E で守られていない挙動があれば、先にテストを足してコミットする（今の挙動を記録するテスト）
2. 前の書き出しを取る（[before-after.md](before-after.md)）
3. gem を上げる。上げ方・一時固定の方法・lock の確かめ方は、設定の「作業ごとの参照」の gems の行
4. lock で動いた gem を確かめる。作業計画にない gem が動いた、一時固定や default gem の版が動いたら止まる
5. 落とした `.gem` を照合する（設定の「道具」）
6. 後の書き出しを取って比べる（[before-after.md](before-after.md)）
7. gem の generator の雛形（initializer・ロケール・上書きしているビュー）が変わっていれば、雛形と比べる。追随は [explain.md](explain.md)
8. 解消した advisory を無視リストから消す（設定の「作業ごとの参照」）
9. アプリごとにコミットする（[commit.md](commit.md)）

## 関門

- 判断の関門: 作業計画にない gem が動く・一時固定が要る、業務的な挙動の変化、gem が未対応のときの方針（設定の「作業のルール」の選び方。決めるのは担当者）
- 理解の関門: gem の既定値・雛形への追随

## 出口の条件と記録

- 上げた gem ごとに、版、一時固定、照合の結果、前後の比較の結果、追随と業務的な挙動の変化を、記録の Step の節に足した。設定の「計画」のチェックリストの、この作業の項目を済みにし、docs のコミットにする（セッションが変わっても、resume が続きから始められるようにするため）
