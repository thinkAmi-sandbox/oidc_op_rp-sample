# rails-lock（Rails のマイナーを上げたときの lock の解決）

## 入口の条件

- 作業計画が承認され、上げる先の Rails の版が決まっている
- 今の Rails のマイナーで上げられる周辺 gem は、先に上げてある（gems）

## 手順

1. 今の Rails が、今のマイナーの最新パッチかを確かめる。違えば、先にパッチを同じ方法（下の 2〜5）で上げ、検査が通ってからコミットする
2. lock のコピーで、旧 lock の gem を固定し、Rails の構成 gem だけを外して解決させる（設定の「道具」の lock の解決）。解決できない gem は、エラーに出た gem だけを外して繰り返す
3. どうしても動く gem と、増えた gem（default gem と同じ名前か）を、作業計画と比べる
4. 一時固定の版を決めて流し直し、その lock をアプリに持ち込む（設定の「作業ごとの参照」の rails-lock の行）
5. 落とした `.gem` を照合し（設定の「道具」）、アプリごとにコミットする（[commit.md](commit.md)）。解消した advisory は無視リストから消す

## 関門

- 判断の関門: default gem を置き換える依存の一時固定、作業計画にない gem が動く、依存で増えた gem のダウンロード

## 出口の条件と記録

- 動いた gem と理由、一時固定、照合の結果を、記録の下書きに控えた
