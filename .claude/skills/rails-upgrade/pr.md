# pr（記録、コードレビュー、PR のタイトルと本文）

## 入口の条件

- verify が終わっている

## 手順

1. 各作業で足してきた記録の Step の節を、設定の「記録」の形に仕上げる（確かめたことだけを書く。比べていないものを「変わらない」と書かない）。設定の「計画」のチェックリストの pr までを済みにする。公開物の安全チェックを通してコミットする
2. コードレビュー（`/code-review`）を流す。指摘ごとに、直す・直さない（理由）を決め、記録の「コードレビュー」に表で残す。直したら、検査と手動確認用の環境を確かめ直す
3. PR のタイトルと、[templates.md](templates.md) の「PR 本文」の型で本文を作る
   - 変更の一覧は、この Step のコミットを 1 行ずつ指す（`git log` で、前の Step の取り込みからのコミットを並べる）。記録の上乗せ（設定の「記録」）の ID も添える
   - 本文を公開物の安全チェックに通してから示す（設定の「ブランチと PR」）
4. 担当者が PR を作ったら、CI の結果を読む（設定の「作業ごとの参照」の pr の行）。失敗していれば原因を調べて直す

## 関門

- 判断の関門: push と PR の作成（担当者が行う）、コードレビューの指摘の扱い
- 理解の関門: PR 本文が、担当者がレビュアーに説明できる形になっているか（変更の一覧の「なぜ」が担当者の言葉で言えるか）

## 出口の条件と記録

- 記録・チェックリスト・コードレビューの表がコミットされ、PR 本文が型に沿って示されている
- 次の Step の始め（resume）で、記録に PR へのリンクを足す
