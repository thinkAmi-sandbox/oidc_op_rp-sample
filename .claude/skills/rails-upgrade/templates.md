# 提示と記録の型

関門で示すもの、コミットと PR に書くものの型。人によっても回によっても、確かめる中身が同じになるようにするため、項目を省かない。当てはまらない項目は「なし」と書く。

## 作業計画（判断の関門。research の出口）

```markdown
## <Step 名> の作業計画

### 目的と範囲
- 上げるもの: <gem・Ruby・Rails と版>
- 上げないもの: <と、その理由・時期>

### 調べたこと
| 項目 | 分かったこと | 出典 | テスト・E2E で守られているか |
|---|---|---|---|

### 決めたいこと
| 論点 | 案 | 根拠 | 見立て |
|---|---|---|---|

### 進め方
- 順番と、コミット・PR の単位
- 判断の関門の予定: ダウンロード（下の型で別に示す）、一時固定、手動確認の時期

### 確かめ方
- 完了条件（設定の「計画」の完了条件のうち、この Step に関わるもの）
```

## 質問（1 回に 1 論点）

```markdown
<何の話かを 1 行>

<本題。根拠になるファイルと行、調べた事実と出典>

<決めたいこと、または食い違っている点>

<見立て>。この見立てでよいですか。
```

- 返事に新しい前提や曖昧な点があれば、同じ論点のまま掘り下げる。結論を自分の言葉でまとめ、同意をもらってから次の論点に移る

## ダウンロードの確認（判断の関門）

```markdown
| 名前 | 版 | サイズ | 入る理由（直接 / <gem> の依存） | 入れ先 |
|---|---|---|---|---|

- 公開日: <版ごと。公開から 2 週間たっているか>
- 照合: 落とした後に SHA-256 を rubygems.org などの値と比べる
```

- 依存で増えるものも含める。default gem と同じ名前の依存は、default gem の版で足りるか（落とさずに済むか）も書く

## 追随の解説（理解の関門。[explain.md](explain.md)）

項目ごとに 1 つ。

```markdown
### <項目>
- 種類: Rails の既定値 / Rails の雛形 / gem の既定値 / gem の雛形 ・ 対象: <アプリ>
- 何が変わるか: <前 → 後>
- なぜ起きたか: <変更の目的。出典の PR・CHANGELOG の要約>
- アプリへの影響: <確かめたこと。スナップショット・設定の値の比較の差分>
- 提案: 追随する / 採用しない（<理由>）
- 出典: <PR・CHANGELOG・gem のソース（gem名-版/ から）・ガイドのページと見出し>
```

- 返事をもらったら、この内容がコミットメッセージの本文になる（設定の「記録」に、記録の上乗せがあればそれにも）

## 業務的な挙動の変化での停止（判断の関門）

```markdown
### 止まった理由: 業務的な挙動の変化
- 変化: <前 → 後>（<スナップショット・テストの差分>）
- 起こした変更: <gem と版 / 設定 / 雛形>
- 出典: <PR・CHANGELOG>
- 設定で元に戻せるか: <戻せる（方法） / 戻せない>
- 選択肢: 元に戻す / 意図的な仕様変更として受け入れる / 上げるのをやめる
- 見立て: <どれがよいか、理由>
```

## コミットの報告（止まらない）

コミットしたら、続けて 1 回ずつ示す。

```markdown
- <コミット> <件名>（単位: <アプリ> / 理由: <1 行>。解説への返事: あり / 不要）
- 検査: <件数の要約>。スナップショットの差分: なし / あり（<理由。追随なら解説の項目>）
- lock: <動いた gem>。一時固定と default gem の版: 動いていない / 動いた（<理由>）
```

## PR 本文（pr の出口）

```markdown
## 概要
<何を、なぜ上げたか。版の表。計画と記録の場所>

## 変更の一覧
| コミット | 変わること | なぜ | アプリへの影響 | 出典・記録 |
|---|---|---|---|---|

## 業務的な挙動の変化
なし（<確かめ方: スナップショット・E2E>）/ 意図的な仕様変更: <変化・理由・承認>

## 確かめたこと
- <検査と件数、前後の比較、手動確認>

## 見送ったこと
- <採用しない雛形、後に回した gem と時期、改善の候補>

## レビュアーに見てほしい所
1. <優先順。業務的な挙動の変化、スナップショットの差分、判断の関門で決めたこと>
```

- 変更の一覧の各行は、レビュアーが差分からコミットメッセージへたどれるように、コミットを指す

## 残す独自設定のコメント

雛形に合わせずに残す設定には、その場所にコメントを書く。次の `app:update` やジェネレーターの差分で、同じ判断をし直さないようにするため。

```ruby
# <なぜ雛形と違うのか>（<決めた記録への参照>）
<設定>
```
