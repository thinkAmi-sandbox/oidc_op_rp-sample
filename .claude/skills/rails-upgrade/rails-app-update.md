# rails-app-update（`app:update` の振り分け）

## 入口の条件

- rails-lock が終わり、新しい Rails で検査が通っている
- 作業ツリーがきれい（独自設定は HEAD から戻すため）

## 手順

アプリごとに、次を行う。

1. アプリのディレクトリで、`app:update` を全上書きで流す
2. アプリの独自設定を戻し、使わない機能のマイグレーションを消す（設定の「道具」の独自設定の戻し）。戻せない項目が出たら、手で戻して道具の一覧を直す
3. 差分を振り分ける
   - 雛形への追随（業務的な挙動は変わらない）: [explain.md](explain.md) の項目にする
   - 新しい構成（設定の「作業のルール」で採用しないと決めたもの）: 採用しない。項目には「採用しない」と残す
   - 業務的な挙動の変化: 止まる
   - 雛形にない独自設定が消えた（道具の一覧にない）: 止まって、残すかを確かめる
4. 解説への返事をもらってから、アプリごとにコミットする（[commit.md](commit.md)）。残す独自設定には、その場所に理由のコメントを書く

## 関門

- 判断の関門: 差分の確認（担当者が `git diff` を見る）
- 理解の関門: 雛形への追随

## 出口の条件と記録

- 採用したもの・戻したもの・採用しないものを、記録の下書きに控えた
